# 需求澄清清单

## 一、结构化 Prompt（初始需求）

```
你是 Python 后端工程师。我需要编写一个静态网页爬虫。
目标：抓取【目标网站 URL】的列表页，提取标题、时间、作者、链接。
约束：使用 requests 和 BeautifulSoup；必须设置 User-Agent 伪装；
请求间隔不低于 2 秒；遇到网络超时需重试 3 次。
验收：输出 result.csv 文件，并在终端打印成功抓取条数。
```

Prompt 按四要素组织，缺一不可：

| 要素 | 内容 |
| --- | --- |
| 角色 | Python 后端工程师 |
| 目标 | 抓取静态列表页，提取 4 个字段 |
| 约束 | requests + BeautifulSoup、UA 伪装、间隔 ≥ 2 秒、超时重试 3 次 |
| 验收 | 输出 result.csv，终端打印抓取条数 |

## 二、需求边界拆解

### 2.1 目标与对象

- 抓取对象：列表页（非详情页、非搜索结果页）
- 目标站点：`http://books.toscrape.com/catalogue/page-{page}.html`

选择理由：真实新闻站点普遍有反爬与版权限制，该站点是公开的爬虫练习沙盒，纯静态 HTML，分页规则清晰，不涉及隐私数据。

### 2.2 字段定义

| 字段 | 含义 | 取值位置 | 缺失处理 |
| --- | --- | --- | --- |
| title | 标题（书名） | `h3 > a` 的 `title` 属性 | 空字符串 |
| price | 时间（价格） | `p.price_color` 文本 | 空字符串 |
| rating | 作者（星级） | `p.star-rating` 的 class 第二值 | 空字符串 |
| link | 链接 | `h3 > a` 的 `href`，用 `urljoin` 转绝对地址 | 空字符串 |

字段映射说明：实验要求提取新闻的标题、时间、作者、链接；本次以练习站点等效字段完成同样的四处抽取训练，映射关系写在上表。

### 2.3 技术约束

1. 请求库固定为 `requests`，解析库固定为 `BeautifulSoup`，不使用 `scrapy` 等重型框架
2. 必须设置 User-Agent，不能使用 requests 默认 UA
3. 相邻请求发起时间间隔不低于 2 秒
4. 网络超时、连接错误最多重试 3 次
5. 任一路由异常不得导致程序中断

### 2.4 验收标准

| 编号 | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | 能成功获取列表页 HTML | 控制台打印 status 与 HTML 长度 |
| A2 | 能稳定提取 4 个字段 | 抽查前 3 条与页面人工核对一致 |
| A3 | 字段缺失不崩溃 | 构造缺字段页面，输出空字符串 |
| A4 | 请求间隔 ≥ 2 秒 | 日志时间戳相邻差值 ≥ 2 秒 |
| A5 | 超时重试 3 次 | 断网/错误域名场景观察重试日志 |
| A6 | 输出 result.csv 且不乱码 | Excel 打开中文正常，列顺序正确 |
| A7 | 终端打印抓取条数 | 运行结束输出总条数 |

## 三、明确不做的事（范围外）

1. 不做登录态抓取、不抓取需要身份认证的页面
2. 不做验证码识别、不绕过反爬策略、不使用代理 IP 池
3. 不做详情页二次抓取（仅列表页四字段）
4. 不做数据库入库、不做可视化看板
5. 不做并发/多线程加速（与"间隔 ≥ 2 秒"的约束目标冲突）

## 四、开发方式约束

采用 Vibe Coding 分阶段方式，禁止一次性生成完整爬虫：

1. 阶段一：仅请求并返回 HTML，运行验证
2. 阶段二：新增解析，仅打印前 3 条，运行验证
3. 阶段三：新增持久化，输出 CSV，运行验证

每阶段的 Prompt 只描述当前阶段要新增的能力，并要求"不改动已验证的代码"，确保迭代可控、问题可定位。
