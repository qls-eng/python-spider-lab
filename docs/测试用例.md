## 二、正常场景

### TC-01 请求层

执行：

```bash
python fetcher.py
```

实测日志：

```
2026-11-18 ... [INFO] 请求成功 [1/3] http://books.toscrape.com/catalogue/page-1.html (status=200, len=...)
```

5 页连续请求，日志时间戳相邻差值不小于 2 秒，无异常退出。

### TC-02 解析层

每页卡片数 20，3 页共解析 60 条；抽查首页 3 条与站点页面人工比对，书名、价格、星级、链接均一致。

### TC-03 持久化

CSV 行数校验结果：

```
total lines: 61  data rows: 60
header: title,price,rating,link
```

### TC-04 编码校验

读取文件首 3 字节：

```
b'\xef\xbb\xbf'
```

即 UTF-8 BOM，符合 `utf-8-sig` 预期；Excel 直接双击打开，中文列头、书名无乱码。

## 三、边界与异常场景

### TC-05 字段缺失兜底

构造输入：一个卡片完全为空，另一个卡片只有书名与价格、无星级。

```python
books = parse_books(html_missing, "http://books.toscrape.com/")
```

实测输出：

```
TC-B row0: {'title': '', 'price': '', 'rating': '', 'link': 'http://books.toscrape.com/x.html'}
TC-B row1: {'title': 'Only Title', 'price': '1.00', 'rating': '', 'link': '...y.html'}
```

结论：缺失字段全部返回空字符串，函数未抛异常，满足"字段缺失不崩溃"的约束。

### TC-06 无效域名（重试机制）

请求 `http://no-such-host-abc123.invalid/page.html`，实测日志：

```
[WARNING] 请求失败 [1/3] ... ConnectionError: Failed to resolve ...
[WARNING] 请求失败 [2/3] ...
[WARNING] 请求失败 [3/3] ...
[ERROR] 重试 3 次后仍失败，放弃该页：http://no-such-host-abc123.invalid/page.html
result: None
```

结论：恰好重试 3 次，间隔按 2 秒、4 秒递增退避，最终返回 None，符合"超时/连接错误重试 3 次"的约束。

### TC-07 404 不重试

请求 `http://books.toscrape.com/catalogue/page-9999.html`，实测日志：

```
[ERROR] HTTP 状态码异常 http://books.toscrape.com/catalogue/page-9999.html -> 404 Client Error: Not Found
result: None
```

结论：状态码异常只记录一次并直接放弃，未进入重试循环，说明重试逻辑只作用于网络层异常，不会因为 404 反复请求。

### TC-08 只抓单页

`python fetcher.py --pages 1` 运行，解析 20 条，CSV 21 行，分页参数生效。

### TC-10 重构等价性回归

步骤 4 把函数式结构重构为 `NewsCrawler` 类后，需要证明"功能不变"。

做法：重构前先备份 `result.csv` 为 `result_before_refactor.csv`；重构后以同一参数 `--pages 3` 重跑，用 `csv` 模块逐行读取两份文件比对：

```
before rows: 61 | after rows: 61
identical: True
```

结论：字段、列顺序、编码、行数、每行内容全部一致，重构未改变对外行为。

## 四、进阶部分（动态渲染站点）

### TC-11 动态页静态解析失效（取证）

对同一页 `http://quotes.toscrape.com/js/page/1/` 用纯 `requests + BeautifulSoup`：

```text
状态码 200   HTML 长度 5806
div.quote 数量 0
含 var data 字样: True
```

结论：HTTP 层正常，DOM 层拿不到卡片。该结果作为"必须渲染或反查数据源"的前提证据，不是失败用例。

### TC-12 方案 B 内嵌数据反查

```bash
python dynamic_crawler.py --strategy inline --pages 2
```

```text
[inline] 第 1 页解析出 10 条
[inline] 第 2 页解析出 10 条
共抓取 20 条，已写入 quotes.csv（utf-8-sig）
```

CSV 22 行（表头 1 + 数据 20），列为 `author,text,tags,page`，首行样例：

```text
Albert Einstein,"“The world as we have created it is a process of our thinking. ...“",change|deep-thoughts|thinking|world,1
```

### TC-13 方案 A 无头浏览器渲染

```bash
python dynamic_crawler.py --strategy render --pages 2
```

```text
[render] 第 1 页渲染后解析出 10 条
[render] 第 2 页渲染后解析出 10 条
```

结论：浏览器执行 JS 后卡片出现，`parse_rendered_html` 用与静态页同一套选择器解析出 20 条。

### TC-14 渲染首访超时与重试

首次实现（超时 25 秒）时第 1 页失败：`等待 div.quote 超时（25.0s），页面可能未渲染`，第 2 页正常。
根因：首访需等 DNS / TLS / 外部 JS 加载，冷启动超过 25 秒。
修正：`page_timeout` 放宽到 45 秒，并对每页加一次重试。重跑后两页均成功。

### TC-15 内嵌标记缺失

构造不含 `var data` 的 HTML 调用 `extract_inline_data()`：

```text
ValueError: 页面中未找到内嵌数据标记 var data，站点结构可能已变更
```

结论：站点结构变更时显式报错，不会静默返回 0 条（与静态站"静默失败"的已知风险相比是改进）。

### TC-16 浏览器不可用

代码路径校验：`find_browser()` 在候选路径均不存在时抛 `RuntimeError("未找到可用的 Edge / Chrome，方案 A 无法执行")`，`main()` 捕获后打印提示并返回退出码 2。本机因存在 Edge 157，该分支未在真实环境触发，标注为**代码路径校验通过、未做真机验证**。

### TC-17 两方案一致性回归

```bash
python dynamic_crawler.py --compare --pages 2
```

```text
方案              耗时(s)     条数      额外依赖
B 内嵌数据反查        5.00      20      无（仅 requests + BeautifulSoup）
A 无头浏览器渲染       19.96     20      websocket-client + 本机浏览器

一致性核对：条数 B=20 / A=20，逐行字段（作者/正文/标签/页码）完全一致
```

同日复测（清理无用依赖后）：B 1.57s / A 6.54s，仍 20 条且逐行一致；绝对耗时随网络与浏览器冷启动波动，相对关系不变。

## 五、未覆盖场景与风险说明

### TC-09 全部页面失败

理论行为：`all_books` 为空，`pd.DataFrame` 生成空表并写入仅含表头的 CSV，程序正常结束。

风险：目前未做 `all_books` 为空的显式提示，使用者可能误以为抓取成功。改进方式是在写盘前判断 `if not all_books: logging.warning(...)`。

### 目标站点改版

项目中所有选择器（`article.product_pod`、`h3 > a`、`p.price_color`、`p.star-rating`）都依赖站点当前 DOM 结构。若站点改版，解析将返回空列表且不报错，属于"静默失败"。当前依靠"每页解析条数"和"总条数"两处输出做人工发现，未做自动化结构校验。

## 六、复现方式

```bash

pip install -r requirements.txt
python fetcher.py --pages 3

# 进阶（动态渲染站点）
pip install websocket-client

python dynamic_crawler.py --compare --pages 2

# 异常复现（任一均可在控制台观察对应日志）
# 1) 无效域名：构造 NewsCrawler(list_url_template="http://<不可解析域名>/page-{page}.html")
# 2) 404：构造 NewsCrawler 时把页码改成超出站点范围（如 --pages 60）
# 3) 单页：python fetcher.py --pages 1
```
