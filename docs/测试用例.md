## 二、正常场景

### TC-01 请求层

执行：

```bash
python fetcher.py
```

实测日志：

```
2026-11-18 ... [INFO] 请求成功 [1/3] http://books.toscrape.com/catalogue/page-1.html (status=200, len=...)
```

5 页连续请求，日志时间戳相邻差值不小于 2 秒，无异常退出。

### TC-02 解析层

每页卡片数 20，3 页共解析 60 条；抽查首页 3 条与站点页面人工比对，书名、价格、星级、链接均一致。

### TC-03 持久化

CSV 行数校验结果：

```
total lines: 61  data rows: 60
header: title,price,rating,link
```

### TC-04 编码校验

读取文件首 3 字节：

```
b'\xef\xbb\xbf'
```

即 UTF-8 BOM，符合 `utf-8-sig` 预期；Excel 直接双击打开，中文列头、书名无乱码。

## 三、边界与异常场景

### TC-05 字段缺失兜底

构造输入：一个卡片完全为空，另一个卡片只有书名与价格、无星级。

```python
books = parse_books(html_missing, "http://books.toscrape.com/")
```

实测输出：

```
TC-B row0: {'title': '', 'price': '', 'rating': '', 'link': 'http://books.toscrape.com/x.html'}
TC-B row1: {'title': 'Only Title', 'price': '1.00', 'rating': '', 'link': '...y.html'}
```

结论：缺失字段全部返回空字符串，函数未抛异常，满足"字段缺失不崩溃"的约束。

### TC-06 无效域名（重试机制）

请求 `http://no-such-host-abc123.invalid/page.html`，实测日志：

```
[WARNING] 请求失败 [1/3] ... ConnectionError: Failed to resolve ...
[WARNING] 请求失败 [2/3] ...
[WARNING] 请求失败 [3/3] ...
[ERROR] 重试 3 次后仍失败，放弃该页：http://no-such-host-abc123.invalid/page.html
result: None
```

结论：恰好重试 3 次，间隔按 2 秒、4 秒递增退避，最终返回 None，符合"超时/连接错误重试 3 次"的约束。

### TC-07 404 不重试

请求 `http://books.toscrape.com/catalogue/page-9999.html`，实测日志：

```
[ERROR] HTTP 状态码异常 http://books.toscrape.com/catalogue/page-9999.html -> 404 Client Error: Not Found
result: None
```

结论：状态码异常只记录一次并直接放弃，未进入重试循环，说明重试逻辑只作用于网络层异常，不会因为 404 反复请求。

### TC-08 只抓单页

`python fetcher.py --pages 1` 运行，解析 20 条，CSV 21 行，分页参数生效。

### TC-10 重构等价性回归

步骤 4 把函数式结构重构为 `NewsCrawler` 类后，需要证明"功能不变"。

做法：重构前先备份 `result.csv` 为 `result_before_refactor.csv`；重构后以同一参数 `--pages 3` 重跑，用 `csv` 模块逐行读取两份文件比对：

```
before rows: 61 | after rows: 61
identical: True
```

结论：字段、列顺序、编码、行数、每行内容全部一致，重构未改变对外行为。

## 四、未覆盖场景与风险说明

### TC-09 全部页面失败

理论行为：`all_books` 为空，`pd.DataFrame` 生成空表并写入仅含表头的 CSV，程序正常结束。

风险：目前未做 `all_books` 为空的显式提示，使用者可能误以为抓取成功。改进方式是在写盘前判断 `if not all_books: logging.warning(...)`。

### 目标站点改版

项目中所有选择器（`article.product_pod`、`h3 > a`、`p.price_color`、`p.star-rating`）都依赖站点当前 DOM 结构。若站点改版，解析将返回空列表且不报错，属于"静默失败"。当前依靠"每页解析条数"和"总条数"两处输出做人工发现，未做自动化结构校验。

## 五、复现方式

```bash
# 正常流程
pip install -r requirements.txt
python fetcher.py --pages 3

# 异常复现（任一均可在控制台观察对应日志）
# 1) 无效域名：构造 NewsCrawler(list_url_template="http://<不可解析域名>/page-{page}.html")
# 2) 404：构造 NewsCrawler 时把页码改成超出站点范围（如 --pages 60）
# 3) 单页：python fetcher.py --pages 1
```
